# Quiz — implementation plan

**Design:** `design/2026-11-23-quiz-design.md` (approved 2026-11-23)
**Shape:** six phases, each ending in something that can be run or seen. Same rhythm as
M1–M6. Phases 1–3 are pure value types and need no view to verify.

---

## Phase 1 — Content: the two new filters

The quiz cannot be generated safely until the content says which pictures are ambiguous
and which letters share a sound.

**`Content/Resources/Alphabet.json`**
- Add `"ambiguousPicture": true` to the 58 words in design Appendix A. Absent elsewhere,
  so the field decodes as `false` and no existing row changes shape.
- Add a top-level `"soundClasses": [["c","k","q"]]` — letters that must never appear as
  each other's choices.

**`Content/LetterCard.swift`**
- `Word` gains `let ambiguousPicture: Bool?`, read through a `var isPictureClear: Bool`
  so the optional is handled in exactly one place.
- `AlphabetFile` gains `soundClasses: [[String]]?`.

**`Content/CardDeck.swift`**
- `soundClass(for:)` returning the group a letter belongs to, or just itself.
- `picturePool()` — every word from the 25 `startsWith` letter cards whose picture is
  clear. This is the single source the quiz draws pictures from.

**Verify:** extend `ContentTests` — exactly 58 flagged; 150 clear; every one of the 25
cards keeps at least one clear picture (this is the test that catches a future content
edit flagging a card's last usable picture); `soundClasses` decodes and C, K, Q resolve to
one group. Confirm the new tests fail when a flag is removed, not just that they pass.

## Phase 2 — The quiz engine

Pure value types, no SwiftUI. This is where the safety properties live.

**`Features/Quiz/QuizMode.swift`** — `pictureToLetter`, `letterToPicture`, `mixed`.
Raw-string Codable for `@AppStorage`.

**`Features/Quiz/QuizQuestion.swift`** — the prompt card, the mode this question is in
(never `mixed`; mixed resolves per question), the correct choice, and three distractors.
A `choices` array built once at generation so render order is stable across redraws.

**`Features/Quiz/QuizRound.swift`** — ten questions, current index, per-question first-tap
outcome. `isFinished`, `dotsFilled`, `advance()`. Clamping arithmetic in the same style as
`PagerPosition`.

**`Features/Quiz/QuizGenerator.swift`** — the seam. Takes the deck, the mode, and an
`inout RandomNumberGenerator`, exactly as `CardDeck.ordered(…using:)` does. Today it picks
eligible letters at random; the adaptive scheduler replaces the inside of this one
function and nothing else moves.

Rules it enforces: ten questions, no letter twice in a round; four choices; distractors
never share the target's sound class; mode B never uses a flagged picture, as answer or
distractor; mode A's distractor letters come from the 25.

**Verify:** new `QuizGeneratorTests` + `QuizRoundTests` — every distractor is wrong; no
flagged picture ever reaches mode B; C/K/Q never co-occur; no repeated letter in a round;
a seeded generator is reproducible and two seeds differ; **every one of the 25 cards can
produce a mode-B question**; round arithmetic at both ends. Break the sound-class filter
on purpose and confirm the C/K/Q test fails.

## Phase 3 — The ledger

**`Features/Quiz/QuizLedger.swift`** — `Codable` value type keyed by letter **and** mode:
times asked, first-tap correct, `lastSeenAt`, and a fixed-length rolling window of recent
outcomes. `recording(firstTap:)`, `cleared()`, and JSON round-tripping to a single
`@AppStorage` string.

Nothing reads it for scheduling yet. It exists so the data is there when the scheduler is.

**Verify:** `QuizLedgerTests` — only the first tap of a question is recorded; later taps
on the same question change nothing; a skipped question changes nothing; the window rolls
at its cap and does not grow without bound; a mode-A answer does not move mode-B numbers;
round-trips through JSON unchanged; `cleared()` empties it.

## Phase 4 — Theme token and the question screen

**`Theme/Theme.swift`** — add `success` with light and dark values.

**`Features/Quiz/QuizQuestionView.swift`** — prompt (large picture, or large letter in the
accent), an instruction line addressed to the parent, four choices in a 2×2 grid reusing
the card-back geometry, and a row of ten dots. Correct tap turns the tile `success`;
wrong tap shakes, dims, stays tappable. Skip and end-round controls styled like the card
front's flip affordance.

Flip state lives in the view as elsewhere; the round lives in `@State` one level up.

**Verify:** extend `ThemeTests` with a contrast check on `success` against both surfaces,
to the same standard §7 holds the others to. Then on device: correct tap, wrong tap,
repeated wrong taps, skip. Screenshot both modes.

## Phase 5 — Start and finish screens

**`Features/Quiz/QuizStartView.swift`** replaces `QuizPlaceholderView` — three mode
choices, Start, and the ledger reset (confirmed before it wipes, placed away from where a
child taps).

**`Features/Quiz/QuizFinishView.swift`** — first-tap score and the letters missed,
addressed to the parent; go again, or leave.

**`Features/Quiz/QuizView.swift`** — owns `QuizRound?` and the ledger, and switches
between the three. Replaces `QuizPlaceholderView` in `RootView`.

`@AppStorage` gains `quizMode` and `quizLedger`.

**Verify:** on device, a full round start to finish in each of the three modes, including
a deliberate wrong answer and a skip, and confirm the finish screen's count matches what
was actually done. Reset, and confirm it clears.

## Phase 6 — Accessibility, spec, and the content audit

- VoiceOver: each choice announces its word or letter rather than a raw emoji; the dots
  announce position; the skip is reachable but not the first thing focused. Correctness
  feedback must be announced, not only shown — a shake is invisible to VoiceOver.
- Dynamic Type to the accessibility-1 cap, as the card back does. Check the 2×2 grid at
  the cap on the smallest supported iPhone.
- Reduce Motion: the shake needs a non-motion equivalent, the way the flip has a
  cross-fade.
- Rewrite **SPEC §9** from "why a placeholder ships" to what the quiz is; add `quizMode`
  and `quizLedger` to the §2 stored-state table; add the quiz tests to §11.
- Fix the §11 drift noted in the design: it still says "exactly 4 words" when §3.5 now
  says pools of 4–10.

**Verify:** VoiceOver pass on device; screenshots at the Dynamic Type cap; full suite
green.

## Risks

- **The 58 flags are judgment, not fact.** They were decided by one person asking "what
  would a three-year-old call this?". Phase 1 is the cheapest point to disagree with any
  of them; after Phase 2 the generator depends on them.
- **Five cards have 1–2 clear pictures** (`i`, `n`, `q`, `y`, `z`), so mode B will repeat
  itself on those letters. Watch for it in Phase 5; the fix is more words on those cards.
- **Mode B tiles are emoji at small size in a 2×2 grid.** The card back proves the
  geometry at four-up, but its emoji sit above a word that disambiguates them. Here they
  stand alone, which is the whole §5 problem — if any flagged-but-kept picture reads badly
  on device, flag it in Phase 1 rather than working around it later.

## Not in this plan

Adaptive scheduling, blends in the quiz, recorded audio, a cumulative progress view,
trend reporting. The seam and the ledger exist for the first of those; the rest are
untouched.

## Afterwards

1.0 has never been submitted and all three builds have expired. Once the quiz lands, the
remaining submission blocker is still screenshots — which should come from the build that
has the quiz in it, not an older one. Shipping the quiz in 1.0 also removes the
Guideline 2.1 risk that the "Coming soon" tab carried.

## Status

All six phases done, 2026-11-23. 98 tests in 10 suites.

Two things changed from the plan as written, both because running it showed something
the design could not:

- **Flagged pictures are barred from mode-A prompts too**, not just mode-B tiles
  (design §5). A prompt the parent has to contradict teaches that pictures cannot be
  trusted, and there are 149 clear ones, so the stricter rule costs nothing.
- **🦪 was flagged** after it came up as a mode-B tile for O. A child names it "shell"
  or "clam", and S and C are both quiz cards. 59 flagged now, not 58.

Risk 2 from the list below held: `i`, `n`, `q`, `y` and `z` are thin on clear pictures,
so both styles repeat themselves on those letters. Two things were done about it:

- **`ice cream` added to `i`** (2 clear → 3). A sweep of the entire emoji repertoire
  found it to be the only word in the five thin letters that passes every gate — see
  `2026-11-23-picture-art-brief.md`.
- **Target selection is weighted by clear-picture count**, capped at four, so `z` comes
  up about a quarter as often as a full card without ever being silenced. This is the
  content-side half of the scheduler; the child-side half still waits on a ledger
  consumer.

The real fix is drawn artwork, which is the art brief's subject.

Left for whoever picks this up: a VoiceOver pass with VoiceOver actually running. The
announcements, labels and reading order are built to the documented API and the code
paths were exercised, but no screen reader has been driven over them.
